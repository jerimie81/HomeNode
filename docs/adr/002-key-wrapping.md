# ADR-002: Key Wrapping & CredentialVault Cryptography on API 28

- **Status:** Proposed
- **Slices Gated:** S3 (`CredentialVault` & Node Identity)

## Decision Question
How should Curve25519 node private keys, SMB/SFTP/WebDAV credentials, and OAuth tokens be wrapped at rest on the Galaxy S8+ (API 28, no StrongBox, no Keystore X25519)?

## Options
- **Option A (Recommended Default):** Direct Android Keystore `AES/GCM/NoPadding` (256-bit non-extractable master key, TEE-backed where reported by `KeyInfo.isInsideSecureHardware`), per-entry random 96-bit IV generated by Keystore, explicit versioned binary envelope, atomic file write in `Context.getNoBackupFilesDir()`, fail-closed (`IdentityUnavailable`) on tamper/invalidation.
- **Option B:** Google Tink `AndroidKeysetManager` backed by Android Keystore master key.
- **Option C:** `androidx.security:security-crypto` (`EncryptedSharedPreferences`) — note: check deprecation status before considering.
